Somatic RNA Fusion Pipeline

Bioinformatics overview of the FFPE RNA-seq fusion-detection workflow: from raw paired-end reads to clinically annotated fusion calls and IGV-ready visualisations.

Pipeline: somatic-fusion-fastq-gpu-v2 (Argo Workflows) · Reference: GRCh38 + CTAT genome lib · Inputs: paired-end RNA-seq with 5 bp UMIs.

1. Overview

This pipeline calls gene-fusion events from paired-end RNA-seq libraries enriched from formalin-fixed paraffin-embedded (FFPE) tumour samples. Each library carries a 5 bp unique molecular identifier (UMI) at the start of every read, which lets the pipeline distinguish biologically distinct cDNA molecules from PCR duplicates that share the same alignment coordinate.

Two independent callers run in parallel:

  • STAR-Fusion — sensitive in known-fusion mode; uses STAR's chimeric junction output to score split-read evidence.
  • Arriba — graph-based event detection; complementary call set especially for atypical events (read-throughs, intra-locus rearrangements).

fusion-report consolidates the two call lists into a single fusions.json that becomes the source of truth for downstream clinical annotation, persistence, and the user-facing report. FusionInspector runs in a visualisation-only role: it realigns reads against per-fusion contigs to produce IGV-ready BAMs but does not contribute calls.

Design principle. A single STAR alignment feeds both callers. UMI-aware mark-duplicates runs between alignment and calling: PCR duplicates get the 0x400 SAM flag set but are not removed from the BAM. Callers see a dedup'd view (Arriba honors 0x400 via -u; STAR-Fusion's chimeric-junction file is filtered by surviving non-dup read names); clinicians inspecting the IGV bundle still see every read with dup status, so the "hide duplicates" toggle in IGV gives them control.

3. UMI extraction & read trimming fastp

Each read in the raw FASTQ begins with a 5 bp UMI introduced during library preparation. fastp performs three jobs in a single pass:

  1. Cut the leading 5 bp from each read and remove them from the read sequence.
  2. Append the UMI to the read identifier (QNAME) as :UMI_<R1bases>_<R2bases>. The 11-character composite token (5 + 1 + 5) becomes the molecular fingerprint that travels through every downstream tool.
  3. Adapter detection / quality trimming on the post-UMI sequence; reads below the length / quality threshold are discarded.
Why UMIs matter for FFPE RNA-seq. FFPE input typically yields short fragments and high PCR-amplification cycles. Without UMIs, two PCR duplicates from the same molecule are indistinguishable from two biologically distinct molecules that happened to fragment at the same coordinate. Coordinate-only dedup over-collapses; UMIs let us tell the difference.

4. Alignment STAR

A single STAR run aligns the trimmed paired-end FASTQ to the GRCh38 CTAT reference. The chimeric-output settings are tuned to recover fusion-supporting reads in two complementary forms:

STAR flagEffect
--chimOutType WithinBAM HardClip Junctions Emits chimeric reads both inline in the BAM (for Arriba) and as a separate Chimeric.out.junction file (for STAR-Fusion).
--chimSegmentMin 10 Allows shorter chimeric segments — Arriba-recommended; better short-fragment recall on FFPE input.
--peOverlapNbasesMin 10 Enables PE-overlap merging when R1/R2 share base content. Recovers junction reads in heavily fragmented inserts.
--alignSplicedMateMapLminOverLmate 0.5 Relaxes mate-map ratio for spliced alignments; preserves split mates that straddle a fusion breakpoint.

The QNAME (with its UMI suffix) survives alignment intact, so the UMI travels into the BAM unmodified.

5. UMI-aware mark-duplicates samtools sort awk QNAME prep fgbio CopyUmiFromReadName fgbio GroupReadsByUmi junction filter

The BAM is coord-sorted and indexed (samtools sort -o ... && samtools index). Then a four-stage dedup pass runs in a single pod, all using off-the-shelf tools:

  1. Strip the UMI_ prefix from QNAME. A samtools view -h | awk | samtools view -b pipeline rewrites every read's QNAME from …:UMI_<R1>_<R2> to …:<R1>_<R2>. The intermediate token cleanup matters because the next step's parser keys off the trailing :-separated field. samtools -@ N parallelises BAM (de)compression around the awk transform.
  2. fgbio CopyUmiFromReadName with --field-delimiter=: --umi-delimiter=_ --remove-umi=true. Reads the now-clean QNAME suffix, splits the paired UMIs on _, joins them with a hyphen and writes them to the canonical RX:Z tag (e.g. RX:Z:GGCTG-ATGTC). Strips the suffix from the QNAME so downstream tools see clean Illumina-format read names.
  3. fgbio GroupReadsByUmi with --strategy=Adjacency --edits=1 --raw-tag=RX --mark-duplicates=true --threads=N. Adjacency is directed-graph UMI clustering — equivalent to umi_tools dedup --method=directional. UMIs within Hamming distance 1 collapse into one cluster, so single-base UMI sequencing errors don't artificially split molecules. The dedup signature is (reference, alignment-start, strand, UMI). Within each cluster, one representative read pair keeps its 0x400 flag unset; the rest get 0x400 set but stay in the BAM. Each read also gets an MI:Z tag identifying its molecular group (audit trail).
  4. samtools sort + index back to coordinate order (fgbio writes template-coordinate sorted output; downstream consumers want coord-sorted).
Mark, don't remove. Earlier iterations used umi_tools dedup which removes duplicates outright. The current architecture marks duplicates instead so the FI consolidated BAM (the IGV bundle) keeps every read with PCR-dup status visible — clinicians can hide dups in IGV but still see full coverage. The calling chain (Arriba, STAR-Fusion-kickstart) consumes a filtered view of the same marked BAM, so call counts in fusions.json still reflect unique molecules.
Why coord+UMI, not coord-only. Coordinate-only dedup (Picard MarkDuplicates) collapses every read pair sharing alignment endpoints into one record. On highly-expressed genes — which fusion partners typically are — this discards real biological signal. On AGI-S5, coord-only reported a 94.4 % "duplicate" rate; UMI-aware dedup of the same library typically lands at 50–80 % because most of the apparent coordinate collisions are distinct molecules with different UMIs.

The STAR-Fusion asymmetry

Arriba reads the BAM and honors 0x400 via its -u flag — so marking duplicates upstream gives Arriba a UMI-aware view for free. STAR-Fusion does not read the BAM; it reads only Chimeric.out.junction, which carries no SAM flags and no UMI awareness. Without intervention, STAR-Fusion would count every PCR-duplicate chimeric read as a separate junction read, inflating per-fusion support.

The filter-chimeric-junction-by-bam task closes this loop: it pulls the non-duplicate read-name set from the marked BAM (samtools view -F 1024) and uses that set to subset the junction file (column 10 = read name). STAR-Fusion-kickstart then sees only UMI-deduped chimeric evidence — its per-call counts in star-fusion.fusion_predictions.tsv match the dedup view Arriba uses.

6. Dual fusion calling Arriba STAR-Fusion (kickstart)

Two callers consume the same UMI-deduped data and produce independent call lists.

Arriba

arriba reads the deduped BAM directly. Its graph-based algorithm identifies discordant read pairs and split-reads across all gene boundaries, classifying events into split-read vs spanning-fragment evidence and assigning each call a confidence tier (high / medium / low) based on a fixed feature schedule. We pass -u as defensive scaffolding (honour upstream BAM_FDUP if any); umi_tools dedup removes duplicates outright so this is a no-op in this pipeline.

STAR-Fusion (kickstart mode)

Rather than rerun STAR (a duplicate ~5 min of compute), we feed STAR-Fusion's calling pipeline the filtered Chimeric.out.junction via --chimeric_junction. STAR-Fusion's bundled scoring logic processes the chimeric records, scores each candidate against its known-fusion DB and the CTAT BLAST/PFAM artefact filter, and emits a TSV of fusions with junction-read, spanning-fragment, and FFPM (fragments per million) counts.

Why two callers. Arriba and STAR-Fusion disagree on ~30–50 % of calls in published benchmarks, mostly because they use different scoring philosophies and chimeric-evidence definitions. Running both and consolidating gives broader coverage than either alone.

7. Consolidation & artefact filtering fusion-report filter-artifact-fusions OncoKB DuckDB

fusion-report merges the Arriba and STAR-Fusion TSVs into a single {sample}_fusions.json. Each entry preserves both callers' native support counts (so users see arriba.split_reads1, starfusion.junction_reads etc. side-by-side) plus a unified label and confidence aggregation.

Artefact filtering (single source of truth)

A dedicated filter-artifact-fusions step then drops well-known non-biological fusion classes from both the consolidated TSV and fusions.json in one place. Every downstream consumer (OncoKB annotator, DuckDB persistence, FusionInspector via the read-extractor) sees the same filtered list, so the user-facing fusions.json never lists artefacts the pipeline never intended to call.

The same regex set lives in images/extract-reads-for-fusion-inspector/extract_reads.py as defensive scaffolding (no-op when input is already filtered); both files note they must stay in sync if the list changes.

Annotation & persistence

The filtered set is then:

  • annotated with OncoKB clinical-significance levels per fusion (oncogenic / level 1–4 therapy mappings);
  • persisted as a per-sample DuckDB file for the cohort-level query / batch analytics path.

{sample}_fusions.filtered.json is the user-facing source of truth for fusion counts and labels — it appears in the MultiQC report, the clinical narrative, and any downstream variant-table consumer.

8. Visualisation: FusionInspector extract-reads FusionInspector propagate-fi-dup-flags

FusionInspector (FI) takes the consolidated gene-pair list and rebuilds a small per-fusion reference: each fusion is represented as a synthetic contig (gene A 5'-region joined at the breakpoint to gene B 3'-region). Reads are realigned to those contigs to produce IGV-ready BAMs that clinicians can inspect directly.

FI is visualisation-only in this pipeline. Its own counts in FusionInspector.fusions.tsv are not the source of truth — fusions.json is. FI's job is to render the supporting evidence in a form a human can look at.

Pre-FI read extraction

FI's runtime scales superlinearly with input read count, so we don't feed it the whole library. The extract-reads-for-fusion-inspector step pulls only:

  • Every read that has a supplementary alignment (flag & 2048) — these are the chimeric / split-read records that constitute the actual fusion evidence.
  • Optionally, reads within ±N bp of a called breakpoint (spanning fragments; disabled by default — see callout below).

The fusion list fed to FI is already artefact-filtered upstream by filter-artifact-fusions (see §7); the extractor consumes the filtered TSV. The Python script keeps a defensive copy of the same regex set as a no-op safety net, but the canonical filter is the upstream task.

Chimeric-only mode. The default is breakpoint-window=0: we extract only supplementary-alignment reads and skip the spanning-fragment window. On AGI-S5 this drops the FI input from ~7.7 M reads to ~244 K — a 32× reduction that takes FI runtime from over an hour to under 10 min. We lose FI's own SpanningFragCount column, but the user-facing counts come from fusions.json (caller-native) so the loss is cosmetic. Set breakpoint-window to a positive integer to re-enable spanning-fragment collection if needed for a specific case.

FusionInspector flags

FlagEffect
--fusion_contigs_only Skip whole-genome STAR realignment; only build per-fusion contigs.
--no_remove_dups Keep every read in the IGV BAM. Dup status is set by the post-FI propagate task (see below), not by FI itself.
--skip_EM Skip fractional read-assignment EM; multi-mapper assignment uses the uniformative-prior fast path.
--vis + --examine_coding_effect Emit the IGV bundle (consolidated.bam + per-fusion .fa + .gtf + cytoBand) and predict coding-effect classes.

Post-FI dup-flag propagation

FI re-aligns reads against per-fusion contigs, which means genome-coord 0x400 flags don't translate through the FASTQ → STAR pipeline naturally. A second post-FI step propagate-fi-dup-flags closes the gap:

  1. Walk the upstream marked BAM and build the set of QNAMEs whose 0x400 flag is set.
  2. Walk FI's consolidated.bam and OR 0x400 onto every record whose QNAME is in that set.
  3. Re-emit the BAM index.

End result: the IGV BAM has every read present, with PCR duplicates flagged. Clinicians can use IGV's "hide duplicates" toggle to view the dedup'd pile, or leave it off to see total coverage at the fusion breakpoint. This was the missing piece in earlier iterations where coordinate-based markdup on small fusion contigs over-flagged 88 % of legitimate fusion-supporting reads as "duplicates" (every fusion-supporting read aligns at the same breakpoint position by construction); QNAME-based propagation transfers the genome-coord verdict correctly into FI's contig coordinate space.

9. QC & reporting CollectRnaSeqMetrics rustqc mosdepth verifybamid MultiQC

QC sidecars run in parallel to the calling chain and feed a single consolidated MultiQC report. The metrics that drive clinical sign-off are:

ToolMetricPass threshold
Picard CollectRnaSeqMetrics PCT_CODING_BASES, PCT_INTRONIC_BASES, MEDIAN_5PRIME_BIAS library-quality fingerprint
mosdepth Coverage over the validated regions BED per-target depth distribution
verifybamid Sample-swap / contamination check FREEMIX < 0.05
rustqc Strand specificity, junction-saturation strand > 0.95 for stranded protocols
fusion-report custom-content per-caller fusion counts + overlap visual sanity check
CollectRnaSeqMetrics chimeric-aware filter. Picard's CollectRnaSeqMetrics throws on chimeric read pairs (mates on different chromosomes). Since our BAM intentionally retains supplementary alignments for the fusion path, we pre-filter the input for this tool only: samtools view -b -f 2 -F 3328 (proper pairs, drop secondary, supplementary, and PCR-duplicate-flagged). The dup exclusion ensures the metrics describe unique molecules. The filter is local to the QC step; the fusion-calling chain still sees the full BAM.
